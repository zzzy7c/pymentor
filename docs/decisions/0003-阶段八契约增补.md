- 日期：2026-10-22
- 状态：**已落地**。以下五条均不改变既有响应字段的语义，`API_VERSION` 不变。
- 触发：SPEC §9 第 1–5 条、§5.20 守护 #38–#45

## 决定 1 · 新增 `api/routers/progress.py` 与 `POST /recommend`

### 背景

`AGENTS.md` §2 的路由清单没有 `/recommend`，但 v4 的 UI 必须有一个 HTTP 入口消费
`recommend_next`；没有端点，这个工具只能存在于测试里，前端要么自己拼业务逻辑
（违反"前端只走 HTTP"），要么没有推荐功能。

### 结论

新增 `POST /recommend`，请求体 `{session_id}`，响应 `RecommendationData`：
`topic / reason / exercise_ids / next_steps / citations`。

- **候选集只来自数据库**（`repositories.list_mistakes(only_unresolved=True)`），
  不来自请求体；模型编造的 `exercise_id` 在 `graphs/progress.py::finalize` 被剥掉。
- 没有任何错题时**不调模型**：服务层用"最少练习的主题"给出确定性推荐，
  `reason` 固定为"你还没有未解决的错题"。
- 引用来自 `rag/citations.py`，检索 query 由主题确定性映射（`_topic_query`），
  不让模型自由发挥引用格式。

### 为什么不是破坏性变更

新增路由不改变任何既有路由、字段或状态码；`schemas.py` 只做追加。按 `AGENTS.md`
§6，新增不是破坏性变更，但需要 ADR —— 即本文件。

## 决定 2 · 新增 `services/usage.py` 作为账本写入的唯一出口

### 背景

`AGENTS.md` §2 把"统计 Token / 成本"划给 `llm/tracing.py`。但那条约束的是**计价**：
把账本写进 `tracing.py` 会让领域层（LLM 客户端）依赖数据库，且配额检查需要读业务表。

### 结论

- `llm/tracing.py` 仍只负责"这次调用花了多少"（`UsageSnapshot` 与单价计算）。
- `services/usage.py` 负责"把这次花费记到谁头上、今天还剩多少"：
  `record_request_usage(...)` 是 `append_token_usage(...)` 的**唯一调用点**。
- 守护 #43 用 AST 断言 `append_token_usage(` 的调用点只出现在 `services/usage.py`。

`AGENTS.md` §2 的所有权表据此增补一行（"写 Token 账本 / 配额检查 → `services/usage.py`"）。

## 决定 3 · `NOT_FOUND` / `RATE_LIMITED` 扩展到业务资源

### 背景

§3.2 的 `NOT_FOUND` / `RATE_LIMITED` 原本只用于传输层（未知路由、slowapi 限流）。
阶段八有两类业务失败需要同样的状态码：

| 场景 | 语义 | 想要的响应 |
|------|------|-----------|
| `exercise_id` 在检查点里不存在 | 调用方错误 | 404 + `NOT_FOUND` |
| 当日本地 Token 配额用尽 | 我们限调用方 | 429 + `RATE_LIMITED` + `Retry-After` |

### 结论

新增 `ExerciseNotFound` / `QuotaExceeded` 两个异常类，`code` 分别复用
`ErrorCode.NOT_FOUND` / `ErrorCode.RATE_LIMITED`，**不新增枚举值**。

- `QuotaExceeded` 与 `LLMRateLimited` 必须分开：前者是我们限调用方，后者是上游限我们；
  状态码同为 429，但码不同，否则报表里"谁被限流"会消失。
- 用户代码报错/超时仍是 200 + `data.status`，不在此列（§3.2 的既有语义不变）。

## 决定 4 · `/health` 增加 `sandbox_ok`

### 背景

v2/v3 的沙箱是宿主 Docker 里的另一个容器。API 进程活着不代表沙箱可用；
部署后最需要回答的问题恰恰是"现在能不能真的跑代码"。

### 结论

`HealthData` 追加 `sandbox_ok: bool | None`（`None` = 未探测）。取值来自
`app.state.sandbox is not None`，只做只读探测，不构造 runner。

- 属**追加字段**，既有消费方不受影响，`API_VERSION` 不变。
- 该字段为 `false` 时，诊断/练习仍可返回降级结果（"未验证"），不产生 5xx。

## 决定 5 · 模型名校验改为后台任务

### 背景

`AGENTS.md` §1 要求启动时调一次 `models.list()` 并与配置比对。同步调用会阻塞
uvicorn 的启动（最长 10 秒网络超时），部署平台的健康检查可能先判死。

### 结论

`lifespan` 里用 `asyncio.create_task(_verify_models_background())`，内部
`asyncio.to_thread(check_models)` + 15 秒外层超时；shutdown 时取消。
校验失败**只降级**：写日志，`/health` 的 `model_check_ok` 反映结果，不影响服务可用性。

`create_app(verify_models=False)` 是默认值，只有生产入口
`app = create_app(verify_models=True)` 打开它 —— 测试不得触网（§5.1）。
